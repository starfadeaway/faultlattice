# FaultLattice 实验操作指南

本指南对应当前已实现的控制台与 CLI。实验预期、故障和 Oracle 必须在运行前写入任务文件；界面不会根据结果反向修改预期。

## 1. 选择实验对象

打开“实验”页，在“实验对象”中选择：

- **内置参考宿主与标准套件**：用于 Harness 自检、参考宿主故障实验和已登记的 M3 场景。选择卡片查看任务内容，再点击“一键运行套件”。
- **已登记的外部 Agent**：只列出当前真实加载和预检通过的适配器。列表来自 `external_agents/registry.yaml`，不包含预检失败项。

若外部 Agent 尚未出现，使用“管理实验对象”进入接入页。上传或生成适配器草案并不等于登记；必须确认代码、填写类名并执行真实加载。只接入明确信任的本地 Python 代码。

## 2. 选择兼容任务

外部对象的兼容任务由系统根据以下事实筛选：

1. 执行模式是否包含在适配器 `capabilities.modes` 中；
2. 任务脚本所需工具是否包含在 `capabilities.tools` 中；
3. 故障注入点是否受支持；
4. M3 是否实现 `CounterfactualHost`；
5. 适配器的 `preflight(fault)` 是否接受该任务。

没有兼容任务时，进入“接入 → 任务创作”，上传 `.yaml/.yml/.json` 任务文件、生成标准任务包或创建自定义任务。保存任务不会自动运行；返回实验页刷新后即可选择。

### 模型选择

- M0 使用预设脚本，不调用真实模型。
- M3 使用页面顶部选定的对话模型。模型、思考模式与采样参数在启动时冻结。
- “设置 → 默认模型”决定下次进入实验页时的初始选择；实验页修改后会同步为新的默认模型。M3 与修改建议共用该选择。
- 修改建议不会修改源码、任务预期或 Oracle 判定。
- embedding-only 配置不能作为对话模型使用。

## 3. 阅读过程与结果

“设置 → 启动后自动定位结果”开启时，启动实验后页面定位到“查看运行过程与结果”；关闭时保留当前阅读位置。“实验完成系统通知”需在设置中主动授权，只在你正在查看的运行中批次结束时通知执行完成或 Harness 错误，不表示 Agent 通过。左侧历史支持按实验对象、批次 ID 和任务 ID 筛选；右侧展示：

1. 实际实验对象、模型和冻结采样参数；
2. 当前任务进度与 Harness 执行状态；
3. 工具调用、注入、工具结果和模型输出轨迹；
4. 框架层与模型层 Oracle 判定；
5. Harness 独立后置状态核验；
6. 可下载的套件 Markdown 报告和可选 LLM 修改建议。

`completed` 表示实验执行与报告复算完成，不表示被测 Agent 没有缺陷。`explicit_failure`、`silent_failure`、`contract_violation` 和 `inconclusive` 应结合任务预注册预期理解；适配器或配置异常会单独显示为 Harness 执行错误。

## 4. 原始产物与复算

每次任务在 `runs/<run_id>/` 生成：

```text
run.json
steps.jsonl
oracle.jsonl
report.md
```

使用 CLI 独立复算：

```bash
uv run faultlattice verify runs/<run_id>
```

本地同步工具真实硬超时可直接运行：

```bash
uv run faultlattice run tasks/local_hard_timeout.yaml
```

该任务使用独立 spawn 进程，记录实际耗时、PID 和进程终止状态，并核对超时后文件未写入。它只回收当前 worker，不保证清理后代进程；smolagents 和 LangGraph 当前显式拒绝 `timeout_mode=process`，不会静默退回模拟超时。

## 5. 页面查找与导航形式

顶部“查找功能”或 Ctrl／Cmd+K 打开功能目录。可以直接搜索“外部 Agent”“任务”“报告”“测试”等关键词，使用方向键选择、Enter 打开、Esc 关闭。

“设置 → 实验与导航 → 导航形式”提供两种可随时切换的布局：

- **领域分组**：主导航保留监测、实验、分析、接入和设置，项目地图等页面从监测子页进入。
- **独立页面**：监测首页、实验、分析、项目地图、模块与代码、测试状态、实验产物、命名登记、接入和设置直接进入主导航，同时隐藏重复的监测子页。

选择会保存在当前浏览器，并随偏好 JSON 导出、导入和恢复默认一起处理。旧版不含 `navigationMode` 的偏好文件仍可导入，此时使用领域分组。

## 6. 评估 Lorekeeper、Anchorline 等外部项目

当前工作区已登记 Anchorline 与 LoreKeeper 的 M0 适配器，并分别完成故障任务和无故障对照。Anchorline 的正常写入得到 `completed`；`memory_write + tool_result` 故障案例确认事实已写入但框架报告失败，Oracle 为 `contract_violation`。这与规范中“任务实际成功 + 框架向调用方返回失败信号”的判定树及对应 golden case 一致；允许宿主明确报失败的降级条款不改变业务任务已经成功的事实。LoreKeeper 的正常计算使用原算式成功返回 `1000`，得到 `completed`；`calculator + tool_args` 故障案例记录除零错误并明确报失败，Oracle 为 `explicit_failure`。

四次均为预设脚本、单次样本且独立复算一致，不代表真实模型行为或稳定成功率、失败率。无故障对照没有 `pair_id`，只作定性比较；LoreKeeper 对照使用了扩展后的适配器，历史故障运行仍保留旧执行哈希，因此不是严格 A/B。四次运行均已提供 `runs/_sample/<run_id>/` 下的脱敏公开四件套，可直接执行 `uv run faultlattice verify runs/_sample/<run_id>` 复算。完整实测值、运行 ID、公开样例链接和命令见 [双项目接入验收报告](../reports/external/2026-11-27-anchorline-lorekeeper-m0-acceptance.md)。其它工具、故障和 M3 仍须按适配器实际能力另行预注册，不能从这四个点外推。

建议按以下顺序评估：

1. **先确认可观测边界**：适配器必须真实暴露任务输入、模型输出、工具参数、工具结果和最终状态；不能只用一段最终回答代替全过程。
2. **再匹配故障能力**：如果 Lorekeeper 的 ReAct 循环能够暴露工具调用与观察边界，可先运行与其能力匹配的 M0 参数、工具返回或观察故障；只有实现 `CounterfactualHost` 并真实支持反事实恢复后，才运行 M3。
3. **为实际任务预注册预期**：内置任务与外部项目不匹配时，在“接入 → 任务创作”建立新任务，明确成功条件、注入点、样本阈值和失败判据，不能强行套用不相关任务。
4. **独立核验外部状态**：如果 Anchorline 的待测路径涉及记忆或持久化，应使用与其实际工具一致的任务，并独立检查内存或存储状态，不能只根据最终文本判定成功。网页表单仍只创建 `file_written` 任务；高级外部任务可使用 `host_state`，但宿主必须实现 `StatefulHost` 并在运行后独立只读观察，未实现或观察失败只能报告“证据不足”。
5. **分开阅读执行状态与实验结论**：`completed` 只表示 Harness 完成执行；`explicit_failure`、`silent_failure` 或 `contract_violation` 才描述被测行为。适配器异常、模型请求失败和证据不足必须单独报告，不能混入 Agent 通过率。

首次接入应先跑一个小型 M0 冒烟场景，人工核对轨迹中的参数与状态确实来自目标项目，再扩大任务集。LLM 修改建议只用于人工复核，不会修改 Oracle 或替代真实复跑。

## 7. 跨批次实验分析

“分析”页直接读取已有套件历史，不重新运行任务，也不修改 Oracle。可按批次、套件、任务和宿主搜索，按内置对象或具体外部 Agent 筛选，并单独查看框架层或模型层判定。

页面汇总匹配批次、任务执行完成数、可判定 Oracle、沉默失败和 Harness 错误；“执行完成”只表示 Harness 流程结束，不表示 Agent 无缺陷。“数据分析结果”用固定规则解释当前样本，分别列出 Harness 错误、沉默失败、显式失败、契约违反、最近批次变化和证据边界，不把显式失败隐去，也不把单批波动写成因果。

动态图表包括判定构成环图、最近 8 个批次的沉默失败率／契约违反率趋势，以及按任务、宿主和模式聚合的风险柱状图。鼠标移动到分区或柱块可看到浮动效果和数值明细；关闭动效时停用进入动画。任务对比保留完整数值，最近批次可跳回实验页复核原始过程。

“大模型辅助分析”使用设置页或本页选定的对话模型。只有当前筛选中的任务全部结束后才可生成，单次最多 300 个任务；后端只发送聚合数量、Harness 状态、错误类型和分层 verdict，不发送完整轨迹、思考原文、源码、本机路径或密钥。模型输出用于解释分布和提出下一步实验建议，不替代原始轨迹中的根因复核。筛选变化后，旧输出会标注“上一筛选范围”，不会自动重新调用模型。

“下载分析 Markdown”保留当前筛选、汇总、规则结论、图表对应数据、任务对比、批次索引，以及范围仍一致的模型分析。“下载 Markdown”按钮也可只下载模型分析及其模型、时间和证据范围。
